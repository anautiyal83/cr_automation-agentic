```yaml

  per_step:
    1: null   # Step 1 (doc parsing) — uses default
    2: null   # Step 2 (UC analysis) — uses default
    3: null   # Step 3 (validation rules gen) — uses default
    4: null   # Step 4 (JSON template gen) — uses default
```

## CR-Automation YAML Schema Contracts

These schemas define the structure that generated YAML configs MUST conform to. They are the cr-automation framework's existing schemas, documented here for reference.

### Validation Rules Schema

`schemas/validation_rules.schema.yaml`

```yaml
# Schema for validation_rules.yaml generated by the pipeline
type: object
required: [uc_name, version, fields]
properties:
  uc_name:
    type: string
    description: Use case identifier
  version:
    type: string
    pattern: "^\\d+\\.\\d+\\.\\d+$"
  fields:
    type: array
    items:
      type: object
      required: [name, type, validations]
      properties:
        name:
          type: string
          description: CIQ column header name
        type:
          type: string
          enum: [string, integer, float, boolean, email, ip_address, ip_subnet, hostname, enum, date, phone]
        required:
          type: boolean
          default: true
        validations:
          type: array
          items:
            type: object
            required: [rule]
            properties:
              rule:
                type: string
                enum: [not_empty, regex, min_length, max_length, min_value, max_value, enum_values, cross_field, custom_python]
              parameters:
                type: object
              error_message:
                type: string
  cross_field_rules:
    type: array
    items:
      type: object
      required: [name, fields, condition]
      properties:
        name:
          type: string
        fields:
          type: array
          items:
            type: string
        condition:
          type: string
          description: Python expression or rule reference
        error_message:
          type: string
```

### JSON Template Schema

`schemas/json_template.schema.yaml`

```yaml
# Schema for json_template.yaml generated by the pipeline
type: object
required: [uc_name, version, template]
properties:
  uc_name:
    type: string
  version:
    type: string
    pattern: "^\\d+\\.\\d+\\.\\d+$"
  template:
    type: object
    description: JSON payload structure with field mappings
    additionalProperties: true
  field_mappings:
    type: array
    items:
      type: object
      required: [json_path, ciq_field]
      properties:
        json_path:
          type: string
          description: JSON path in template (e.g., "$.device.hostname")
        ciq_field:
          type: string
          description: CIQ column header that provides the value
        transform:
          type: string
          description: Optional transformation (e.g., "upper", "strip", "custom_func")
        default_value:
          type: string
          description: Default if CIQ field is empty
```

### Workflow Schema

`schemas/workflow.schema.yaml`

```yaml
# Schema for workflow.yaml generated by the pipeline
type: object
required: [uc_name, version, workflow_type, steps]
properties:
  uc_name:
    type: string
  version:
    type: string
    pattern: "^\\d+\\.\\d+\\.\\d+$"
  workflow_type:
    type: string
    enum: [cli, rest, mixed]
  steps:
    type: array
    items:
      type: object
      required: [step_number, name, action_type, action]
      properties:
        step_number:
          type: integer
        name:
          type: string
        action_type:
          type: string
          enum: [cli_command, rest_api, pre_check, post_check, wait, conditional]
        action:
          type: object
          properties:
            command_template:
              type: string
              description: CLI command with {variable} placeholders
            method:
              type: string
              enum: [GET, POST, PUT, DELETE, PATCH]
            url_template:
              type: string
            headers:
              type: object
            body_template:
              type: object
            variables:
              type: array
              items:
                type: object
                required: [name, source]
                properties:
                  name:
                    type: string
                  source:
                    type: string
                    enum: [ciq_field, previous_step_output, static, json_template]
                  value:
                    type: string
        expected_output:
          type: object
          properties:
            pattern:
              type: string
              description: Regex or template for response matching
            success_indicator:
              type: string
            error_indicators:
              type: array
              items:
                type: string
        on_failure:
          type: string
          enum: [abort, retry, skip, continue]
          default: abort
        timeout_seconds:
          type: integer
          default: 60
  rollback_steps:
    type: array
    description: Steps to execute on workflow failure
    items:
      type: object
      # Same structure as steps
```

### Simulator Config Schema

`schemas/simulator_config.schema.yaml`

```yaml
# Schema for simulator I/O config generated by the pipeline (step 6)
type: object
required: [uc_name, mock_entries]
properties:
  uc_name:
    type: string
  mock_entries:
    type: array
    items:
      type: object
      required: [command_pattern, response_template]
      properties:
        command_pattern:
          type: string
          description: Regex pattern matching the CLI command or REST endpoint
        response_template:
          type: string
          description: Simulated response with {variable} placeholders
        response_code:
          type: integer
          description: HTTP status code (for REST) or exit code (for CLI)
          default: 0
        delay_ms:
          type: integer
          description: Simulated response delay
          default: 0
        variables:
          type: object
          description: Variable values to inject in response template
```
