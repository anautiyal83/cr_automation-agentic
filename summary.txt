  Google ADK vs Current Approach (Direct liteLLM)

  What We Have Now

  Plain Python classes with execute() → litellm.acompletion() → OpenRouter. Simple, works, but no framework features.

  My Recommendation

  Don't adopt ADK now. Here's why:

  1. Our pipeline is sequential, not multi-agent — each step feeds the next, no parallel coordination needed
  2. We already have working HIL + milestone review — ADK's HIL would require rewriting this
  3. Steps 7-9 are deterministic — ADK agents are overkill for schema validation and report generation
  4. The NiceGUI frontend is independent — ADK's dev UI doesn't help us
  5. Migration cost is high for marginal benefit

  Consider ADK later if:
  - We need parallel agent execution (e.g., steps 3-5 running simultaneously)
  - We want to deploy agents as standalone services
  - We add more complex multi-agent workflows (e.g., agent-to-agent negotiation)
